# Как добавлять контент без правок кода

Весь контент (дерево тем, статьи) хранится в обычных таблицах Supabase. Чтобы добавить новую статью или картинку, ничего не нужно программировать — открываете **Supabase Dashboard → Table Editor** и вставляете строки. Приложение читает их напрямую, без пересборки и без меня.

Разово перед первым использованием: примените [supabase/migrations/0002_article_image_blocks.sql](supabase/migrations/0002_article_image_blocks.sql) в SQL Editor (добавляет поддержку картинок в блоки статей).

## Порядок добавления новой статьи

1. **`tree_nodes`** — узел в дереве тем (то, что видно в разделе «Дерево тем»).
2. **`articles`** — сама статья (заголовок, теги, сложность).
3. **`article_sections`** — оглавление статьи (для правой панели TOC).
4. **`article_blocks`** — содержимое статьи: абзацы, заголовки, код, картинки и т.д.

### 1. `tree_nodes` — где статья появится в дереве

| Колонка | Что вписать |
|---|---|
| `id` | уникальный текстовый id, например `node_yoga` |
| `parent_id` | id родительского узла, или `NULL` — если это новый раздел верхнего уровня (сейчас верхний уровень — `node_root`, чтобы добавить раздел рядом с «Растяжка»/«Гитара», укажите `parent_id = node_root`) |
| `code` | номер по порядку, например `4.` |
| `title` | название в дереве, например `Йога` |
| `level` | глубина: у `node_root` = 0, у разделов верхнего уровня = 1, у статьи внутри раздела = 2 и т.д. |
| `has_article` | `true`, если по клику открывается статья |
| `article_id` | id статьи из таблицы `articles` (следующий шаг) |
| `sort_order` | порядок среди соседей (0, 1, 2...) |

### 2. `articles`

| Колонка | Что вписать |
|---|---|
| `id` | уникальный id, например `article_yoga_basics` — именно его укажете в `tree_nodes.article_id` |
| `code` | например `4.1.` |
| `title` | заголовок статьи |
| `tags` | массив текста, например `{Йога, Здоровье}` (в Table Editor — поле-массив, добавляете элементы кнопкой) |
| `difficulty` | ровно одно из: `Легкий`, `Средний`, `Продвинутый` |
| `read_time_min` | число минут чтения |
| `category_path` | массив текста для хлебных крошек, например `{Йога, Основы}` |
| `likes_count`, `comments_count` | можно `0` |
| `total_pages` | любое число (используется только для отображения «N из M») |

### 3. `article_sections` (оглавление)

По одной строке на пункт оглавления:

| Колонка | Что вписать |
|---|---|
| `id` | уникальный id, например `yoga_sec_1` |
| `article_id` | id статьи из шага 2 |
| `parent_id` | `NULL` для пункта верхнего уровня, id другой секции — для вложенного подпункта |
| `code`, `title` | например `1.`, `Введение` |
| `sort_order` | порядок |

### 4. `article_blocks` — само содержимое

По одной строке на каждый абзац/блок, `sort_order` = порядок сверху вниз. Обязательно: `id` (уникальный), `article_id`, `sort_order`, `type`, `content`.

| `type` | `content` | доп. поля |
|---|---|---|
| `paragraph` | текст абзаца | — |
| `heading` | текст заголовка | `level` = `2` или `3` |
| `code` | текст/код как есть, многострочный | `language` — любая строка, например `text`, `javascript` (только подпись, без подсветки синтаксиса) |
| `callout` | текст выноски | `callout_type` = `info` / `warning` / `success` |
| `list` | пункты списка **каждый на новой строке** внутри одного текстового поля | — |
| `image` | **URL картинки** | `alt_text` — подпись/альт-текст (необязательно) |

## Картинки

Поле `content` для блока `image` — это просто ссылка на картинку. Два варианта, откуда её взять:

**Вариант A — своя картинка в Supabase Storage (рекомендую):**
1. Dashboard → **Storage** → **New bucket** → назвать, например `article-images` → включить **Public bucket**.
2. Открыть бакет → **Upload file** → загрузить картинку.
3. Кликнуть на загруженный файл → **Get URL** (или «Copy URL») → это и есть публичная ссылка.
4. Вставить эту ссылку в `content` блока типа `image`.

**Вариант B — любая внешняя ссылка:** можно указать прямую ссылку на картинку с любого хостинга (в том числе с телефона через любой сервис загрузки фото) — работает точно так же, загружать в Supabase не обязательно.

## Проверка

После вставки строк просто обновите страницу приложения — новый пункт появится в дереве, статья откроется с реальным содержимым. Если статья не открывается или показывает не то — проверьте, что `tree_nodes.article_id` совпадает с `articles.id`, а `article_blocks.article_id`/`article_sections.article_id` совпадают с тем же `articles.id`.
